# Protocol Simulation Tool Inventory

Baseline commit inspected: `524d4b0` (`origin/main`).

## 1. Verification of Status-Report Claims

A repository-wide grep of `backend/app/tools/` and `backend/app/compute/` showed why a search for `simulator_tools.py` or `pta` tool names came up empty:

1. **No `simulator_tools.py` exists** (a previous unreviewed draft was reverted in `e269809`). The existing `"simulator"` agent tools are defined inside `backend/app/tools/pkmodel_tools.py` (`run_dose_sweep`, `run_clinsim`, `run_exposure_forest`, `run_special_population`, `run_individual_exposures`, `run_pediatric_simulation`) and in four uncertainty/design modules (`bootstrap_tools.py`, `sir_tools.py`, `profile_tools.py`, `simest_tools.py`).
2. **Existing trial simulation (`run_clinsim` -> `clinsim.clinical_trial_simulation`) is single-stratum and single-replicate**: it simulates one virtual cohort across a 1D dose grid against a single threshold (`> threshold` or `< threshold`) without covariate bands, without regimen dosing intervals (`tau`), without simultaneous efficacy-window + peak/trough safety limits, and without replicate loops or Monte Carlo standard error (`mc_se`).
3. **Existing special-population and pediatric tools (`run_special_population`, `run_pediatric_simulation`) are not plan-driven**: they run fixed default strata with a hardcoded seed (`20250614`) rather than filtering to the bands and seed approved in `protocol_sim.plan`.
4. **Existing uncertainty tools (`run_bootstrap`, `run_sir`, `run_profile`) do not propagate parameter uncertainty into PTA**: they estimate parameter confidence intervals (`bootstrap_results`, `sir_results`, `profile_results`) in isolation, without an outer loop over parameter draws/bounds into band-by-regimen PTA intervals.
5. **No fit-precondition loader (`load_approved_fit`) or structured simulation-plan proposal tool (`propose_simulation_plan`) exists**.

## 3. Build List Executed Before Registering Workflow

1. **`PharmState` extension (`backend/app/core/pharmstate.py`)**:
   - Add `protocol_sim: dict[str, Any] | None = None` wrapped in `ProtocolSimDict(dict)` so both dict key (`state.protocol_sim["plan"]`) and attribute (`state.protocol_sim.plan`) access work seamlessly while serializing as a standard JSON object.
   - Grant `"modeler"` (for `load_approved_fit`) and `"simulator"` (for simulation/uncertainty steps) write permission to `protocol_sim` in `AGENT_WRITE_FIELDS`.
2. **Protocol simulation compute & tool layer (`backend/app/compute/protocol_sim.py`, `backend/app/tools/protocol_sim_tools.py`, `backend/app/tools/builtins.py`)**:
   - `load_approved_fit`: enforces `nlme_results.status == "ok"` and `review_results.goal_met is True`, captures covariate and maturation data ranges from the source dataset/fit, and writes `protocol_sim.source_fit` + `protocol_sim.provenance`.
   - `propose_simulation_plan`: constructs and validates `protocol_sim.plan` (`bands`, `regimens`, `metrics`, `target_window` with provenance, `n_subjects`, `replicates`, `seed`, `uncertainty_method`) and records `plan_hash` in `protocol_sim.provenance`.
   - `run_dose_sweep` (in `backend/app/tools/pkmodel_tools.py`): reads `protocol_sim.plan` doses/tau/route and `protocol_sim.source_fit` when present in state.
   - `simulate_trial_pta`: simulates virtual cohorts across `replicates` per band and regimen using the plan's seed, computes steady-state `auc`, `cmax`, and `ctrough`, evaluates target window attainment and peak/trough safety limits, computes replicate mean PTA and Monte Carlo SE (`mc_se`), and selects recommended regimens per band with their driving metric.
   - `simulate_special_populations`: runs `clinsim.special_population_simulation` and `clinsim.pediatric_simulation` strictly for the bands named in `protocol_sim.plan` using the plan's seed.
   - `propagate_parameter_uncertainty` (`expensive=True, proposable=True`): runs `bootstrap`, `sir`, or `profile` as specified in `protocol_sim.plan.uncertainty_method` and propagates the resulting parameter draws/bounds as an outer loop into `pta_ci_lo` / `pta_ci_hi` per band and regimen.
3. **Adversarial review extensions (`backend/app/compute/adversarial.py`)**:
   - Six simulation-specific refutation checks in `_protocol_sim_refute`, each blocking at `HIGH` severity and recording the inspected `target` field.
4. **Report section (`backend/app/tools/report_tools.py`)**:
   - `"Protocol simulation"` section rendering the approved plan table, PTA per band per regimen with MC SE and parameter-uncertainty interval, recommended regimen per band with driving metric, every `HIGH`/`CRITICAL` review finding and its disposition, and the provenance block (handling skipped optional steps gracefully).
